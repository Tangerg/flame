## 2. 本轮新增发现

- **N-1 [P2][可用性] 启动恢复时，单个 Session 的资源退休失败会让整个 Runtime 拒绝启动。**
  - 位置：`application/agent/sessions/resource_retirement.go: RecoverRetiredResources`。

## 5. 分模块明细（第一轮原文；已按 b1ea765 原位标注状态，未标注者经复核仍成立）

## 1. runtime/internal/domain

### 1.1 domain/run（Run 聚合）

- **[P1][one-fact] 终态被四套分类重复表达**（`run/lifecycle.go`, `run/status.go`, `run/failure.go`, `run/run.go:validateTerminal`）
  `State{running,waiting,completed,failed,canceled}`、`Outcome{completed,canceled,timedOut,failed,lost}`、`Status{running,waiting,finished}`、`FailureKind{...,lost,timeout}` 四者对“Run 是否结束、为何结束”各存一份。终态 `State` 完全可由 `Outcome` 推出（`Outcome.terminalState`），`FailureKind.Lost`≡`OutcomeLost`，`FailureKind.Timeout`≡`OutcomeTimedOut`。`validateTerminal` 正是“两个表示不一致时谁赢”的仲裁规则，证明它们能各自前进。
