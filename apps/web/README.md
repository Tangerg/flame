# Shared Web product

This React application runs in Browser and Wails. Runtime owns durable business
semantics; Web owns inputs, view projections, navigation and presentation.
[ARCHITECTURE.md](ARCHITECTURE.md) records feature, extension and lifetime owners.
The [native host](../desktop/README.md) supplies macOS capabilities without owning
another UI application.

Desktop web and mail links use one document activation adapter in
`src/platform/externalLinks.ts`, installed by the composition root. It hands
external HTTP(S) and mailto destinations to Wails' system-browser API while
retaining native anchors, their captured addresses and ordinary keyboard
activation. Cancelled events, downloads and local navigation keep their existing
owners. Browser mode retains its native link behavior. A refused desktop open
keeps a localized, dismissible error with its destination; it never retries or
navigates the application to the external page. Teardown removes both listeners
and retires later feedback.

Shared Callouts receive their kind titles from the application locale through
`CalloutLabelsProvider` at window and installed-component roots. The i18n React
binding observes dictionary additions and removals, so lazy activation and locale
retirement update mounted readers without another label store.

Image previews and exports share one inline-image contract. Export decodes the
image in an inert image context and rasterizes it as PNG before calling the host's
file-save boundary. SVG source never crosses that boundary as executable material;
animated formats export a still frame. Browser reports download dispatch, while
Desktop reports a completed write or cancellation. The download action names PNG
explicitly. [SVG image contexts](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image)
disable scripts and external resource loading.
Streamed native save failures preserve both transfer and cleanup diagnostics in
the visible error; an unconfirmed cleanup is never reported as cancellation.

From the repository root:

```sh
make setup
make dev-web
npm run check --workspace @flame/web
```

Root npm workspaces and lock select all dependencies. Shared packages must be
built by `make setup`/`make generate`; do not create a package-local install or
lock. `make stage-web` builds the same production output used by native embed.

`index.template.html` owns the Web entry structure. Product identity, native
packaging metadata and the actual appearance owners feed `tooling/presentation.mjs`,
which generates the entry HTML, prepaint script, base stylesheet, native canvas
constants and packaging projections during `make generate`. Edit those owners,
then regenerate; `check-bootstrap.mjs` checks the complete generated bytes.

`src/bootstrap.ts` checks the browser capabilities required by the application
before evaluating `main.tsx` or its dependencies. Missing capabilities receive a
selectable, localized upgrade diagnosis; module-load failures retain their cause
and provide a reload action. The early page uses only generated presentation
variables and a small DOM renderer. It does not initialize React, Runtime, installed
components or their locale bundles. Its diagnostic text is projected from the
Host's eight bundled catalogs during presentation generation; an unavailable
locale uses English without replacing the saved preference. Normal locale
activation and withdrawal retain their existing owners.

The authored Component SDK runtime profile owns the browser compilation targets
for components, this application and the Lab. The current support floor is Chrome
137 or Safari/WebKit 26. Native composed selection ranges are required for
precise clipboard projection from installed Shadow DOM readers. The native macOS installation floor is separate: macOS
14 needs software updates that provide the required WebKit capabilities. The
startup check tests capabilities, rather than inferring them from an OS version
or user-agent string. Compilation does not polyfill runtime APIs.

The production build emits `.vite/flame-artifact-graph.json` from its actual
chunks, source declarations and final HTML. The bundle guard verifies emitted
bytes before counting the bootstrap static closure and the explicitly immediate
main import together. Import-map targets alone are not startup requests. Lazy
groups come from those declarations and use their source identities and dependency closures, with shared
startup files counted once and each group's additional bytes reported separately.
HTML prefetch hints remain separate from startup parsing. These are build-graph
observations, not first-paint, runtime-fetch or latency acceptance thresholds.

`webPolicy.mjs` owns the built document and program-frame security policies.
`webArtifacts.vite.mjs` publishes their current schema with final artifact digests.
HTTP and Wails consume that same distribution through `local-runtime/webassets`.
Each main HTML response pairs one cryptographic nonce with its script attributes,
Vite preload nonce and CSP header, returns `no-store` with a fresh 200 response,
and denies embedding through `frame-ancestors 'none'` and `X-Frame-Options: DENY`.
Trusted modules may load verified installed ESM. Parser-inserted scripts require
a nonce; dynamic loading inherits trust under
[CSP strict-dynamic](https://www.w3.org/TR/CSP3/#strict-dynamic-usage). Eval is not
authorized. The independent opaque GenUI program response and the exact
privacy-enhanced YouTube frame origin retain their separate embedding contracts.
The existing Lab `component` and `fixture` document declarations permit only
same-origin embedding, with the same strict script policy; gallery and shipping
main documents retain `DENY`.

Immutable caching requires a build-owned content fingerprint and verification of
the served bytes against the final distribution digest. JS uses the bundler's
actual hash-placeholder provenance; emitted assets use SHA-256 names. StyleX emits
one complete stylesheet before asset hashing instead of rewriting named CSS or JS.
Web, Lab and the Vitest suites select the shared UI's `stylex` export condition, so the same
transform compiles shared and application atomic styles once. The shared CSS import
then supplies document rules; standalone consumers retain the complete precompiled
stylesheet through the ordinary package exports.
Unfingerprinted public appearance scripts, focus scripts and fonts remain
revalidatable. A stale policy or altered registered file is refused; registering
an arbitrary filename alone does not establish a content fingerprint.

The sidebar and Context Dock use `react-resizable-panels` for layout and resize
input. The Dock separator paints the seam at the same edge the group uses for
the resize target. Its expanded hit region leaves both panel minimums available.
After a user resize, shell preferences save the group's requested layout when
available and its settled layout otherwise.

The fixed, clipped application root owns the viewport frame. Reading surfaces own
their scrolling, so native input focus cannot scroll the application chrome away.
Workspace reading viewports reserve the shared inset focus perimeter with a
transparent border. Scrolled content clips at its inner edge, keeping both the
perimeter and the area above sticky controls clear of document fragments.
The explicitly focusable source/preview `ScrollArea` reserves the same border
inside that frame. File-action visibility uses its inner clipping edges and the
fractional viewport bounds, so feedback reveals only a previously visible action
that the new layout actually clips.

Settings navigation reveals its currently selected category inside its own
scrollport after a resize or selection change, moving only as far as needed.
A visible or search-hidden selection leaves the rail where the user scrolled it.
Editing focus and the retained page position remain owned by that page.
Optional category icons occupy a stable column using the shared icon size and
row gap, so built-in and contributed labels share one logical leading edge.
The rail reserves one complete navigation row and its existing bottom padding;
at short stacked sizes the open pane yields enough space to keep that row usable.
The existing geometry observer supplies the header's actual height to that cap,
so the navigation does not duplicate the header's control or spacing dimensions.

`src/app` composes product policy. `src/features` contains actual feature owners
and their formal public capabilities. `src/extensions` contains generic host,
registration and lifetime mechanisms; it never owns business extension points.
`src/platform` translates Browser/Wails effects. `src/ui` contains product
presentation composites over shared `@flame/ui` controls and tokens.

Recorded JSON formatting belongs to `@frame/sdk/json`: `prettyJSON` indents values
through the exact codec, while `formatJSONText` changes only captured source
whitespace. Agent projections, approval drafts, Tool inspection and conversation
archives consume those helpers directly, sharing numeric preservation with
portable reading components.

Pending approval arguments can be edited locally. Cancel or Escape from the
editor restores the original arguments, clears validation feedback and focuses
Edit. An admitted approval makes the editor read-only until settlement. Its
captured arguments remain visible while the response is pending.

Tool inspection keeps arguments secondary when a specialized result presentation
owns the body, including an empty captured page. Without a specialized presenter,
the generic inspector opens arguments when the result body is absent or empty.

Expanded images, figures and captured documents use shared `LightboxDialog`.
The transcript gallery retains collection, active-image and save-command ownership
and uses shared `ImageViewport` for fitting, zoom and panning. Portable evidence
images use the same reading boundary, with their captured source and local labels.
The Mermaid lightbox shows its current zoom on the actual-size button. The
diagram viewport shows keyboard focus inside its edges and supports arrow-key
panning through the existing transform controls. While new diagram text
settles, the last accepted diagram or source fallback stays available. A
render failure closes the lightbox and transfers focus to the source reader
when the retiring diagram owned it. Recovery restores the inline diagram and
moves focus there if the source still owns it. The lightbox opens on request.

The composition root creates each feature instance and its backing state once.
React consumers use that owner's Provider; commands and plugin factories capture
explicit dependencies. Tests construct independent instances in `test/renderClient.tsx`,
and visual fixtures compose them in `lab/scenarios/client.tsx`. No default feature-instance
registry or module-global port installer is part of the product API.

Provider settings keep mutation generations and sensitive credential drafts in
one explicitly composed feature instance. A command captures its original
generation and rejects after retirement. Runtime replacement clears that
instance's drafts; disposal cannot affect another instance's commands or drafts.

MCP settings receive their mutation owner from the composition root. Editors,
enablement, authorization, tool exposure and reconnect capture that instance's
current command generation. Runtime replacement retires those commands; plugin
shutdown retires the generation and renderer shutdown disposes the owner.

Goal commands and composer mode belong to one explicitly composed feature
instance. Commands retain their admitted Runtime generation, including a pending
replacement confirmation. Each submission captures its Session, objective and
model options before confirmation. Model options cannot replace the Session or
objective. Resetting composer mode invalidates its submission
settlement, so a late reply cannot accept or change a newer draft in the same
Session. Plugin shutdown retires Runtime work and resets mode; renderer shutdown
disposes both owners.

Project hook trust captures the command generation supplied by its feature
Provider. Trust writes remain serialized per project through canonical query
revalidation. Runtime withdrawal retires pending and queued intent, and a stale
control cannot submit that intent through a successor Runtime.

Message feedback keeps optimistic selection, accepted ratings and subscriptions
inside its explicit feature instance. The UI reads that instance's current
projection and captures its submission generation. Runtime replacement clears
the retired projection, while late replies and stale controls cannot alter or
submit through its successor. An absent Runtime supplies no command generation.

Question drafts retain raw text and one literal custom choice, including commas.
The editor can explicitly skip a field with an empty answer. Runtime admits the
complete candidate. The final skip action is labeled Skip and submit because it
sends the earlier answers with the last field empty. Web preserves whitespace
and duplicate answers before submission.
While an answer is pending or staged, the footer actions stay focusable and
refuse activation through the shared disabled-control contract; incomplete and
offline forms keep native disabled actions. The same command projection keeps
choices and fields read-only, and refuses late pointer, paste or IME changes,
until canonical history replaces the admitted answer or submission becomes
available again.

Conversation search covers revealed message text, including text reached by
scrolling. Collapsed, hidden and inert content is excluded regardless of its
mounting history. Expand a disclosure to include its content; closing it updates
the count and retires its ranges. Search reads that visibility projection and
preserves the disclosure and keyboard focus owners.
Closing Find restores the original Composer's last editing selection when its
mounted document is still current. The Composer owns that return through
Lexical, and the search bar retains its ordinary return for other controls.

File reading navigates adjacent bounded line windows using Runtime's served
start and end coordinates. Earlier pages retain their requested end at the byte
cap; later pages begin after the served end. The reader requests Runtime's
maximum admitted response budget so every permitted source line fits whole.
Line references begin at the requested line. An in-reader line jump shows its
destination beside the line summary while the current page remains visible.
If Runtime rejects the line request, the reader keeps the current page while it
is cached and shows the rejected destination. Go to line remains available for
a corrected line number. While the cached page is displayed for a local jump or
page request, the reader keeps its reading mode, source mark and position. An
accepted line jump opens Source at the requested line. When the result
removes a focused mode option or control inside the preview, focus continues
in the file reader.
While an adjacent page loads, the reader keeps the current page visible and
shows a loading status at the activated edge. The other paging action is
unavailable during that read. If the read fails, the reader offers to retry the
requested line range and keeps the previous page while it is cached. If a retry
removes the focused action while that page stays visible, focus returns to the
reader. An accepted page starts at its top, while a refresh retains that page's
reading position.
Source selection and copy refer only to the presented page. Partial pages stay
in source mode, and the header shows their actual served line range. For a whole
file the header shows its line count.
The file reader scopes Select All to its displayed content in both Preview and
Source, excluding its path and host controls. Source highlights the mounted code
for the current page. Preview retains native formatted copy. Source and renderer
fallbacks copy the literal captured page as plain text. Nested code readers and
editable fields keep their own selection behavior.
In Source, Left and Right pan the rendered code column. The named file
viewport owns vertical reading and keeps arrow keys from returning focus
to a retained Composer selection in both Preview and Source. Tables and code
blocks own their horizontal panning. With a retained Composer selection, a
focused nested reader uses its own vertical scroll range or the nearest
enclosing vertical viewport within the reading scope.

The workbench keeps its layout and existing Runtime recovery notice available
before the first Session snapshot. Conversation content starts from a defined
snapshot, including a known empty list. Request activity can change while that
snapshot is still absent, so it cannot remount the recovery action or create an
empty conversation. Explicit workspace views remain reachable during that wait.
The existing connection status owns the notice and automatic retry; its action
opens the Connection settings pane. Closing Settings returns to the retained
conversation region, with the same recovery action next in the Tab order. Once
Session data arrives, the existing Composer presents connection feedback and
retains its draft and focus through later connection status changes.

Image selections belong to their Session draft as pending, ready or failed
attachments from the moment they are chosen. Send remains unavailable until all
retained images are ready. Failed selections stay visible for removal and
reselection. Reads complete against the original Session, in selection order,
even while another Session is active. Clearing, replacing or discarding that draft
retires its pending selections. Reads run one at a time. Removing a selection,
clearing/replacing/discarding its draft, endpoint replacement and disposal abort
the active FileReader and remove queued reads. Returning to a retired endpoint
retains ready images and shows cancelled pending images as removable failures;
they cannot remain indefinitely preparing. Replacement at the same endpoint and
ordinary Session navigation preserve authorized reads. Image bytes and read
intents remain in memory; only draft text and pasted text are persisted.

Composer owns asynchronous IndexedDB draft persistence, keyed by endpoint and
Session. Each commit writes only changed Session records. Pasted text has separate
immutable records; ordinary typing writes compact references without cloning
unchanged paste bodies or serializing other Sessions. One commit is in flight per
endpoint and queued revisions of the same Session coalesce to the latest draft.
Only transaction completion confirms saving. A request that later aborts cannot
confirm a draft. Pending commits participate in the exit warning.

Storage refusal retains the latest draft and original failure cause beside the
input without interrupting image preparation or settlement of accepted input.
Explicit Retry saves current pending changes, including cleared or discarded
drafts, without resending a message. Inactive endpoint owners retain their pending
or failed revisions. Loading never overwrites later edits or explicit removals;
untouched Sessions and image-only selections can still receive saved text.

A failed read never authorizes writing an initialized empty collection. Retry can
restore the saved collection before authoring changes; subsequent authoring keeps
the unread bytes intact and requires explicit recovery. Copy draft text captures
the unconfirmed text and separate pasted-text records on request, including
inactive targets, without copying connection credentials or claiming images are
durable. A late copy cannot confirm a later draft. Recovery reads its text synchronously
in the click and starts clipboard I/O in that same activation. It reports through
the same immutable copy receipt as every other copy action.
The Retry presentation captures its original input on focus and returns it in
pre-exit layout cleanup only while Retry still holds focus. A stable ref merely
binds the button; a failed retry or a ref rebind cannot return focus.
Hiding that presentation or replacing its Composer owner permanently retires the
capture. After reveal, a new focus entry can capture the original input again.

Draft storage is IndexedDB schema version 2. Each Session record holds the ordered
draft content of text and file references plus its paste references. Opening a
version 1 database converts its records once inside the upgrade transaction: a
stored editor checkpoint whose every node is understood keeps its file references,
and any other record keeps its complete text. An unrecognized record stays untouched
and reading it requires explicit recovery. No runtime reader or localStorage
projection of an older shape remains.

The page installs an exit warning only while the Composer owner reports
unconfirmed changes. Cancelling departure and persisted page transitions keep
the same renderer; nonpersisted pagehide and explicit HMR retirement use its
existing disposal path. Page departure cannot guarantee completion of asynchronous
cleanup; Runtime leases retain their existing authority.

Explicitly removing an image, referenced file or pasted text returns focus to the
current Composer input with the remaining draft and attachments; the removal
itself does not place the caret or select text.
Automatic draft refreshes and paste review dialogs keep their own focus owners.
The attachment tray retains its natural row height inside the existing bounded
editor scroll area. A short window cannot shrink it through a text chip or image
control; the toolbar keeps its own space and the input retains its existing
reading and focus behavior.

Root Run notifications consume settlements published after an atomic live-event
commit, including Runs that start and finish in the same frame. Each settlement
carries its Run and Segment identity; a parked cancellation receipt has no active
Segment. Duplicate event folds, rejected batches and retired projection generations
cannot publish another settlement. Cold reads and history refreshes stay quiet.
Accepted cancellation receipts use the same committed transition projection.

Each window starts notification producers only after its Base UI Toast Provider
exposes the public command capability. One Provider owns the live queue, four-second
ordinary lifetime, persistent errors and interaction pauses. All live messages remain
readable in the bounded notification band; Action and localized Close controls use
normal keyboard order. The window's notification feed owns its separate in-memory
history. Closing a Toast never marks history read, and clearing history never closes
live feedback. Cancelled departure, visibility changes and persisted page transitions
retain this capability; actual window retirement revokes it before producer disposal.
Feature presentations compose public Base UI primitives at their behavior owner;
shared controls retain their token, accessibility and cross-host contracts.

Session title editing captures the Session ID, revision, original title and command
port when Rename opens. List refreshes cannot retarget that edit. Summary writes
preserve the captured revision even when queued behind another write; Runtime owns
conflict admission. A refused edit retains its draft and feedback. Cancel and reopen
Rename to capture a newer target. Enter and blur share one pending submission.
Missing-workspace edits capture the same Session precondition. A Session switch
cannot rebind a path draft, and a late result cannot clear another edit.

Accepted Composer Stop returns to the captured input without consuming its draft
or moving its selection. Refused Stop keeps its action context; later focus and
input replacement remain with the existing captured-focus owner. Send, Steer and
Stop use the shared focusable-disabled contract while commands are unavailable.
The Runtime retains cancellation admission and Run settlement ownership.

A draft has one representation: ordered content of text and file references.
Its prompt text is a projection, because Runtime input carries text. Lexical owns
the mounted document, selection, composition, undo and typeahead; plain text is one
paragraph with line breaks, so a restored newline stays one newline. The editor
checkpoints its content in one direction. Accepted file candidates create typed
references; manually authored `@text` remains ordinary text. Commands that change
the draft (history recall, quoting, restoring a paste, message editing, starting a
reference or command) run once as a domain transition whether or not an editor is
mounted, and a mounted editor then presents the result. References therefore
survive every command, and an unchanged checkpoint is not an edit, so recall keeps
its place. Composer key bindings receive submission only, never a text writer.
Source changes remount with the captured checkpoint. Submission captures a content
revision, so a late acceptance cannot clear newer edits. Enter inserts a newline,
Mod+Enter submits, and Mod+ArrowUp/Down explicitly recalls history.
TanStack Hotkeys owns shortcut parsing, recording, matching and display. Commands
run in the bubble phase and respect defaultPrevented and editable ownership.

Opening a past message for editing asks before replacing a draft with images
or pasted-text attachments. Cancel returns to the message and preserves the
draft. Confirmation applies to the captured draft, Session and storage scope.
The resolved result reaches the existing Composer only after the dialog closes.
Editing through a history rewind uses the same confirmation before requesting
rollback. The confirmation describes whether files are restored. The request
checks the original Session and root Run before launch. When the rollback
commits, Composer applies the recovered prompt only while the captured draft
is current.

File suggestions show the filename above its complete wrapping parent directory
before insertion. Literal path text keeps directory then filename in DOM order,
with the exact path in the accessible name, hover title and accepted reference.

Regeneration keeps rollback and follow-up admission under one captured Agent
command lease. Only a committed rollback with Runtime's original dropped input
can submit another Run in that Session. Missing targets, unavailable checkpoints,
retired endpoints and joined operations never fall back to a displayed prompt.
File-restoring actions require a preceding root Run in the current projection;
the fresh Runtime read and rollback still decide whether restoration can commit.

Manual Goal-mode exit uses that same captured Composer focus. Accepted exit
returns to the current input with its draft and selection intact; later focus or
an input replacement retires the capture. The exit is an ordinary named action.
Automatic mode retirement and Goal execution keep their existing owners.

TextEditorDialog derives modal dismissal from its existing busy state. While
saving, Close, Escape and outside dismissal share the same unavailable contract
as Cancel and Save. Settlement restores dismissal; draft, error, command and
return-focus ownership remain with their existing callers and shared controls.

After a Goal save conflicts with a Runtime change, the editor leaves the
draft editable and shows the latest loaded objective beside the feedback.
The existing Session projection supplies that objective when the user decides
whether to revise the draft, save again or cancel.

Installed component recovery keeps Reload window focusable while its original

refused cleanup retains the recovery action and diagnostics without reclaiming
later input focus. Render failure and retired resources use this same recovery
boundary. Component retirement and actual window reload keep their existing owners.

An independently mounted component's render failure returns lost owned focus to

The same mount hands current reader focus to that host before its upstream

Package configuration keeps local validation feedback with the open edit. It
formats syntax, object-shape and request-field errors as correction instructions
and derives field validity from that one message. Editing or cancelling retires
that validation. Command feedback retains the existing asynchronous owner and
remains available after a refused edit closes.

The Composer footer wraps controls in source order when their actual sizes no
